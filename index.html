1.1 Giới thiệu đề tài

Đề tài tập trung nghiên cứu cấu trúc nhị phân của tệp thực thi Windows Portable Executable (.EXE), kết hợp kỹ thuật phân tích tĩnh (Static Analysis) và phân tích động tự động (Dynamic Analysis) trong môi trường máy ảo cô lập sử dụng Cuckoo Sandbox, đồng thời trực quan hóa toàn bộ dữ liệu hành vi lên giao diện Web SOC Dashboard.

1.2 Lý do nghiên cứu

Các biến thể mã độc hiện đại thường sử dụng kỹ thuật làm rối (obfuscation), nén (packing) và né tránh phát hiện dựa trên chữ ký tĩnh truyền thống. Việc giám sát trực tiếp hành vi hệ thống (tiến trình, Registry, File System, Network) thông qua Sandbox tự động giúp nâng cao khả năng nhận diện mối đe dọa và giảm rủi ro phân tích thủ công.

1.3 Mục tiêu dự án
  • Xây dựng mô hình Lab ảo hóa cô lập an toàn (Windows Host – Ubuntu Server – Windows Guest VM).
  • Tự động hóa trích xuất đặc trưng PE Header, IAT và Shannon Entropy qua thư viện pefile.
  • Tích hợp RESTful API giao tiếp với Cuckoo Sandbox và chuẩn hóa báo cáo JSON lên Web Dashboard.

9 RESEARCH MODULES

1. Introduction (Giới thiệu)

Hệ thống tự động hóa quy trình tiếp nhận, kiểm tra cấu trúc nhị phân và theo dõi hành vi thực thi của tệp .exe trên nền tảng web tập trung.

2. Research Objectives (Mục tiêu)

Rút ngắn thời gian phân tích sơ bộ (triage), kết hợp chỉ số tĩnh và động để đưa ra phân loại mức độ rủi ro (Clean / Suspicious / Malicious) có giải thích rõ ràng.

3. Research Scope (Phạm vi)

Tập trung vào tệp thực thi Windows PE32/PE32+ (.exe), triển khai trong mạng nội bộ cô lập (Host-Only), không kết nối Internet công cộng khi chạy mẫu.

4. Malware Analysis

Quá trình mổ xẻ cấu trúc, chức năng và tác động của một tệp nghi ngờ nhằm xác định cơ chế lây nhiễm, giao tiếp C2 và mức độ nguy hại đối với hệ thống.

5. Static Analysis (Phân tích tĩnh)

Kiểm tra mã nhị phân mà không thực thi tệp: tính toán mã băm, phân tích cấu trúc PE Header, bảng hàm nhập (IAT), chuỗi ký tự và độ hỗn loạn Entropy.

6. Dynamic Analysis (Phân tích động)

Thực thi tệp trong môi trường giám sát (Sandbox) để ghi nhận hành vi thực tế: tạo tiến trình con, chỉnh sửa Registry, ghi/xóa tệp và kết nối mạng.

7. Sandbox Technology

Cơ chế cô lập tài nguyên cho phép chạy chương trình không đáng tin cậy an toàn, sau đó khôi phục máy ảo về trạng thái sạch ban đầu (Snapshot Revert).

8. Cuckoo Sandbox Architecture

Gồm máy chủ quản lý (Ubuntu) điều phối qua mạng ảo tới Agent chạy bên trong Windows Guest VM để hook API và thu thập báo cáo hành vi JSON.

9. Technologies Used

Kết hợp VirtualBox, Ubuntu Server, Windows 10 Guest, Cuckoo Sandbox REST API, Python FastAPI/Flask, pefile, HTML5/CSS3/JS và Chart.js.

TECHNICAL GLOSSARY

Portable Executable (PE) & PE Header

PE là định dạng tệp thực thi tiêu chuẩn của Windows (.exe, .dll, .sys). PE Header (gồm DOS Header, NT Headers, File Header, Optional Header và Section Table) chứa siêu dữ liệu giúp Windows Loader nạp mã vào bộ nhớ, xác định kiến trúc (x86/x64), Entry Point và các phân đoạn như .text, .data, .rsrc.

Import Address Table (IAT)

Bảng cấu trúc bên trong tệp PE liệt kê các thư viện liên kết động (DLL) và các hàm Windows API mà chương trình gọi tới (ví dụ: VirtualAlloc, WriteProcessMemory, RegSetValueEx). Phân tích IAT giúp dự đoán ý đồ hành vi trước khi chạy tệp.

Shannon Entropy (Độ hỗn loạn thông tin)

Thước đo tính ngẫu nhiên của dữ liệu byte trong từng Section (thang đo từ 0.0 đến 8.0 bits/byte). Các Section có giá trị > 6.8 bits/byte thường là dấu hiệu tệp đã bị nén (Packed bằng UPX, Themida) hoặc mã hóa payload để qua mặt phần mềm diệt virus.

MD5, SHA-1, SHA-256 & ImpHash

Các hàm băm mật mã tạo ra "dấu vân tay số" duy nhất định danh tệp. Trong đó SHA-256 là chuẩn tra cứu Threat Intelligence chính xác cao, còn ImpHash (Import Hash) băm danh sách hàm nhập giúp nhận diện các biến thể cùng một họ mã độc.

Sandbox Isolation (Cô lập môi trường)

Thiết lập ranh giới bảo mật nghiêm ngặt giữa Host Machine và Guest VM bằng card mạng ảo Host-Only Adapter, vô hiệu hóa Shared Folders/Clipboard và sử dụng Snapshot sạch để ngăn mã độc thoát ly (VM Escape) hoặc lây lan ra mạng thật.

RESTful API

Giao thức giao tiếp chuẩn HTTP/JSON giúp Backend Python gửi tệp mẫu tới Cuckoo Sandbox (POST /tasks/create/file), truy vấn tiến độ (GET /tasks/view/{id}) và tải báo cáo phân tích (GET /tasks/report/{id}) một cách tự động.

Thông số môi trường triển khai (8 Thành phần hệ thống)

1. Host Machine

Máy tính vật lý chạy Windows 10/11 Pro (64-bit), bật ảo hóa phần cứng Intel VT-x / AMD-V, đóng vai trò điều hành Hypervisor và trình duyệt giám sát SOC.

2. Oracle VM VirtualBox

Phần mềm ảo hóa quản lý 2 máy ảo tách biệt và thiết lập card mạng nội bộ Host-Only Adapter (vboxnet0) đảm bảo cô lập lưu lượng mã độc.

3. Ubuntu Server

Máy ảo Linux (Ubuntu 20.04/22.04 LTS) cài đặt lõi Cuckoo Sandbox, MongoDB/PostgreSQL, TCPDump và dịch vụ Python Backend API.

4. Cuckoo Sandbox

Framework phân tích mã độc tự động điều phối vòng đời máy ảo, thu thập API calls, file dropped, registry changes và lưu lượng PCAP.

5. Windows Guest VM

Máy ảo Windows 10 (64-bit) tắt Windows Defender/Firewall nội bộ, cài đặt Python và agent.py, lưu trạng thái sạch qua Snapshot clean_win10.

6. Web Backend

Dịch vụ trung gian viết bằng Python FastAPI/Flask thực hiện phân tích tĩnh bằng pefile, lưu giữ bí mật API Token và chuẩn hóa JSON.

7. Frontend

Giao diện Web SOC chuẩn HTML5, CSS3, JavaScript ES6+ và Chart.js hoạt động hoàn toàn trên trình duyệt mà không thực thi mã nhị phân.

8. API Integration

Giao tiếp RESTful API nội bộ giữa Frontend ↔ Backend (/api/*) và Backend ↔ Cuckoo Sandbox (/tasks/*) có cơ chế timeout và xác thực Bearer Token phía server.

Tài liệu kỹ thuật & Đặc tả API (Technical Documentation)

1. Project Introduction & Architecture

Hệ thống phân tách rõ tầng giao diện người dùng (Browser) với tầng xử lý nghiệp vụ (Ubuntu Python Backend) và tầng thực thi nguy hiểm (Windows Guest VM). Mọi tệp tải lên được kiểm tra kích thước, định dạng PE và băm SHA-256 trước khi đưa vào hàng đợi Sandbox.

2. Installation Overview

1. Cấu hình VirtualBox Host-Only Network (192.168.56.1/24).
2. Cài đặt Cuckoo Sandbox & MongoDB trên Ubuntu Server.
3. Cài đặt Python + agent.py trên Windows 10 Guest và tạo Snapshot.
4. Khởi chạy FastAPI Backend (uvicorn main:app --port 8000).

3. Đặc tả RESTful API (Internal Backend & Cuckoo Sandbox API)

Layer Method Endpoint Mô tả chức năng & Tham số
Backend API POST /api/analyze Nhận tệp .exe (multipart/form-data), kiểm tra PE, chạy pefile và đẩy sang Cuckoo.
Backend API GET /api/tasks Trả về danh sách lịch sử các phiên phân tích đã lưu trong cơ sở dữ liệu.

Backend API GET /api/system/status Kiểm tra kết nối thực tế tới Cuckoo API, Guest VM và Database.
Cuckoo REST POST /tasks/create/file API gốc của Cuckoo Sandbox tiếp nhận mẫu tệp nhị phân kèm header Authorization: Bearer <SERVER_TOKEN>.
Cuckoo REST GET /tasks/view/{id} Truy vấn trạng thái máy ảo và tiến trình phân tích của Task ID trong Cuckoo.
Cuckoo REST GET /tasks/report/{id} Trích xuất báo cáo JSON thô từ Cuckoo Sandbox sau khi hoàn tất phân tích động.

Lưu ý kỹ thuật tích hợp Cuckoo Sandbox vs CAPE & Bảo mật API Token

• Phiên bản API: Cấu trúc endpoint và trường JSON của Cuckoo Sandbox 2.0.x khác với CAPEv2 (ví dụ đường dẫn submit và cấu trúc trường info.score / malscore). Backend cần kiểm tra phiên bản Cuckoo trước khi ánh xạ dữ liệu.
• Bảo mật Token: CUCKOO_API_TOKEN chỉ được lưu trong biến môi trường phía Backend Server (.env), tuyệt đối không nhúng vào mã JavaScript phía trình duyệt và không mở cổng Cuckoo API ra Internet công cộng.
